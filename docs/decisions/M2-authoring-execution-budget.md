This is a new allocation for the implemented authoring/scenario slice, separate from the consumed provider engineering smokes. It authorizes local, nontraining verification only after M3's current product review passes. The user requests code completion and available non-GPU checks; no remote or paid compute is authorized or needed here.

Use the already acquired, manifest-verified MLX model and dependencies identified in `docs/interfaces-M2.md` and the retained authoring-envelope receipts. No downloads, backend substitution, model change, or memory-policy widening. Native execution remains in the bounded provider worker; all baseline/application and generated discovery commands remain inside reviewed M3 Docker workers.

Before each distinct discovery/contract/scenario request, record its exact serialized request, derived proposal schema, prompt/context identities and allowed retrieved spans. Measure the actual request with the pinned offline tokenizer and worker chat template. Set the input cap to measured tokens plus twenty percent rounded up to the next 1,024 tokens, with an absolute cap of 16,384; set the output cap to 4,096. If the measured input does not fit, retain a precise capacity failure or reduce only irrelevant context through an explicit recorded retrieval decision. Do not truncate undisclosed requirements or silently rewrite context.

Per call, retain existing maximum 120-second wall and CPU limits, 1 MiB stdin/output/file caps, 3.5 GiB MLX guideline/wired limits, zero cache budget, 4 GiB sampled-footprint kill threshold at 20 ms and the disclosed 5 GiB declared ceiling with guard. These are existing enforcement limits, not newly measured capacity claims. No other memory-heavy native check or historical Docker suite should run concurrently with inference. Recheck available host capacity before the first load.

The first actual structured call at its frozen envelope is also the larger-envelope capacity measurement. This supersedes the earlier coordinator suggestion of a separate disposable qualification generation: reusing the real attempted output avoids an extra model run without pretending capacity is already proven. Archive success, truncation, memory failure, known partial costs and actual token evidence before deciding whether the output can be accepted. A capacity failure does not authorize widening limits.

Each repair requires a diagnosed cause and recorded changed input. Do not spend remaining calls repeating an unchanged capacity failure. No paid-cost estimate is invented; unknown GPU/money/human components stay null.
