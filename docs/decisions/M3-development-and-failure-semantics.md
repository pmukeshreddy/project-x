# M3 development execution and attributable failure

Coordinator rulings during the first production runtime implementation. These settle downstream interfaces; they do not claim that the current code or failed first B-health run passes these gates.

Ruling: a development command must remain runnable when saved source cannot build. The learner must be able to inspect files and repair a syntax/build error using the same bounded sandbox and source-capture policy. A successful matching `BuildResult` cannot be a prerequisite for every development command. Edits followed by a test/import within one command must observe that command's current source through an explicitly documented development environment. M3 should expose this path distinctly from the fresh candidate rebuild and installed-wheel execution used by trusted grading. Any changed runtime recipe/semantics is recorded and reverified; no shadowed package or host execution is acceptable. If this separation is missed, a normal learner error can make the workspace impossible to repair or cause tests to exercise stale code.

Ruling: ordinary candidate-caused build or source-export failures preserve the exact last-confirmed source and receive an attributable typed outcome. Deleting the source directory, creating unsupported links, or exceeding source-capture bounds is not by itself proof of a Docker platform failure. Daemon, monitor, controller storage and cleanup faults remain distinguishable infrastructure failures with their actual evidence. M4 must be able to recover that distinction without guessing from a string or treating every build exception as a valid candidate zero. An unverified cleanup cannot produce a normal successful execution receipt. If attribution is unresolved, record the unresolved measurement rather than invent a reward.

The first baseline regression run failed and remains failed. Diagnose it from preserved output and runtime state before changing setup. Supported behavior-neutral repairs are already authorized for local execution: record the cause and exact correction, apply consistently to B/H/candidates, and rerun affected checks. Do not suppress failing assertions, relabel a failed health run, or change feature semantics to make H pass. These implementation diagnostics do not consume a fabricated completed-task result or imply feature qualification.
