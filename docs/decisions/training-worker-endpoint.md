# Explicit worker endpoint for deferred CUDA execution

The implemented M3 track uses a Linux arm64 Docker daemon and the pinned Click image; SkyRL training is planned for a Linux x86_64 CUDA controller. These are separate roles. Static inspection by the M3 owner and coordinator confirms `DockerEngine(socket_path=...)` sends both Docker CLI commands and HTTP API 1.47 requests through the supplied absolute Unix-socket endpoint. Its architecture checks apply to the daemon/image, not the controller CPU. The controller uses POSIX primitives available on Linux; no Darwin-only product dependency was identified.

M7/M6 must accept an explicit worker socket in their configuration. A CUDA controller can use an independently configured, protected Unix-socket forwarding endpoint to the supported arm64 daemon. The operator must establish/authenticate that endpoint outside the project. Do not automatically provision hosts, start SSH connections, expose an unauthenticated Docker TCP listener, forward credentials into workers, or silently select local x86 Docker. The project checks endpoint connectivity and daemon identity but does not authenticate the tunnel or verify socket permissions.

Deferred setup commands must declare the arm64 worker, compatible Docker CLI/API, exact retained images, dependency artifacts, private persistent controller state and forwarding endpoint as prerequisites. Run the actual M3 qualification through that endpoint before any candidate work; latency must fit existing bounds. Both CLI duplex execution and HTTP control must work. Never equate an absolute socket path or static source inspection with verified forwarding.

This is the initial supported deployment topology, not a new x86 worker recipe or a claim that remote execution ran. Forwarded Linux-controller execution remains **unverified**. M3's local arm64 execution evidence remains valid only for its recorded environment. A future native x86 worker recipe would require an explicit M3-owned extension with its own pinned image and boundary verification; it is not silently substituted by the training launcher.
