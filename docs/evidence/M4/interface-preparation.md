## Minimal proposal and finalization boundary

Actual M0 `Scenario` contains prose: `preconditions`, `actions`, `observations`, `expected_relation`, `input_domain`, `reset_needs`, plus `scenario_id`, `requirement_ids`, and `oracle_origin: EvidenceLink`. It is not an executable comparison language. Actual `CaseDefinition` already provides `inputs: ArtifactRef` and `comparison: ArtifactRef`; `WorkerAdapter` provides `code`, `version`, `supported_observables`, and `limitations`. These extension points suffice; no shared-interface blocker or duplicate M0 schema is presently justified.

Propose one strict M4-local checker proposal comprising worker setup/adapter source and per-scenario case-domain/observation/comparison specifications. Reuse actual M0 nested types and preserve `FieldInfo`/`Annotated` constraints for any projected shared fields, following the M2 finalization ruling. The controller fixes the input contract/plan references, admitted requirement and scenario IDs, resource/seed policy, and generation identities. The model proposes the grounded semantics and worker source; it does not invent receipts, final artifact hashes, timestamps, measured costs, a frozen contract, or a Click answer. Use M2's `checker_generation` stage with exact frozen contract/plan context and attributable allowed request/B/public-check context; no H context.

The sole new controller language is a closed, versioned, non-executable M4 data schema. Each case specification names its scenario, requirement IDs, bounded input slots, ordinary observations, and assertions. Each assertion has a unique local assertion ID, explicit disclosed requirement IDs, an observation selector, a tagged comparison, and the scenario's `oracle_origin` plus any additional admissible grounding links. Selectors are bounded field/index paths into a declared observation schema, not expressions or method names. Literal/domain operands are strictly typed, with bounded sizes/depth/counts and exact Boolean/integer distinctions. No `eval`, import, generated comparator callback, executable deserialization, or model-written case generator runs in the controller.

Finalization resolves and checks evidence, performs the joins below, archives the raw proposal and actual M2 call/cost receipts even on rejection, then materializes private M4 input/comparison/manifest objects. M0's store accepts local canonical JSON as opaque `put_bytes(..., kind, visibility)` objects, not new unregistered `ArtifactModel` subclasses; M4 must independently parse and strictly validate those payloads on every read. Assemble and validate the real M0 `CaseDefinition`, `WorkerAdapter`, and `VerifierBundle` with controller-owned provenance/costs, then `put_artifact`. Setup/adapter source remains untrusted bytes executable only through reviewed M3; any setup recipe change goes through the owning upstream boundary and creates new dependent versions.

## Proposed initial semantics and explicit limits

These are implementable initial semantics, not capabilities demonstrated by this note or a frozen Click contract:

| Observation or construction | Closed initial support |
| --- | --- |
| Real CLI invocation | Supervisor-observed integer process exit status and bounded stdout/stderr text, with explicit decoding policy. Do not confuse process status with an adapter-reported API exit code. |
| Small serialized public API adapter | Declared fields containing null, exact Boolean/integer/string values, or bounded ordered arrays of those values; adapters invoke the actual interface and return observations, never authoritative verdicts. |
| Comparisons | Type-sensitive exact equality; scalar membership in a declared finite set; literal text containment; exact ordered-array equality; equality of two declared observations. Each operator needs specific contract grounding. No implicit case-folding, trimming, sorting, or exact error formatting. |
| Seeded input construction | Controller-built deterministic selection from declared finite typed choices, bounded integer ranges, and explicit string concatenation templates. Include required fixed/boundary cases and at least one case from every mandatory family before adding seeded variations. Freeze generator algorithm/version, domain, complete realized inputs, IDs, and seed before execution. |

Unsupported initially: arbitrary formulas/regexes or executable generators, floating tolerance, implicit text parsing/normalization, callback/object identity semantics, concurrency/timing guarantees, and file/service side effects without an independently controlled observation adapter. More complex justified metamorphic relations need a reviewed new operator; they cannot be hidden in generated controller code. Membership/containment alone may underconstrain a requirement: reject a shallow checker rather than treat operator support as adequate coverage. No suggestion ordering, wording, normalization, or public exception behavior is presumed for Click.

Only the current probe's inputs and required untrusted adapter/setup material reach its worker. The full seeded input inventory, comparison data, expected values, ledger, other cases, H and controls stay out of candidate workers. A worker necessarily sees the input it executes; private inputs do not mean inputs can remain secret from that invocation. Public tests remain diagnostics; a reward-bearing compatibility obligation needs an external probe. Untrusted API observations are ordinary data, not independently trustworthy attestations; real adversarial/semantic controls must challenge forgery and hard-coding.

## Exact finalizer and grading joins

1. Resolve bounded, integrity-checked exact references: `TaskBundle.private_oracle` to verifier; task/verifier/plan `contract` references all equal; verifier `scenario_plan` resolves to that exact plan. Check task/environment baseline equality and adapter-version equality, dependency/source identities, partition/visibility policy, and the authorized frozen/admission version. A typed reference or `state` string alone proves neither existence nor freezing/qualification.
2. Let R be all feature plus compatibility requirement IDs, and M their `mandatory=true` subset. Require the plan's mandatory IDs to be duplicate-free and exactly M. Reject duplicate/unknown scenario requirement IDs; every mandatory requirement needs meaningful coverage. M0 only checks a coverage subset, not this dereferenced equality.
3. Each local case maps to an existing scenario; its requirement IDs and every assertion's IDs are nonempty, duplicate-free subsets of that scenario's IDs and R. The union of assertion IDs' requirement mappings equals the case's requirement set; mandatory assertions across realized cases cover M. Case `mandatory` must agree with the frozen scoring policy and cannot downgrade a mandatory requirement. Preserve all mandated scenario families on every seed, not merely one case for each requirement.
4. Join every assertion's oracle origin to the source/locator/quote and the contract/scenario evidence and admitted provenance. Verify source existence, exact cited text, admissibility, and whether that evidence actually entails the comparison. Unknown/excluded/unresolved behavior cannot become a private assertion. A changed interpretation returns to M2 and invalidates dependent evidence; H output never silently supplies the rule.
5. Bind each `CaseDefinition.inputs` and `.comparison` payload to its case/scenario/requirement IDs, declared observation schema and generator version. The frozen input payload defines fixed values/domain slots; a separate immutable grading manifest records their seed-derived realization. Keep case IDs/counts fixed across seeds and require exact case-set equality with `completion_manifest`; do not mutate the frozen verifier when sampling. Require unique assertion/probe identities and freeze the complete seed-specific probe ledger before execution. Receive exactly one bounded, schema/type/ID-valid observation for each expected probe; missing/duplicate/unknown/skipped probes, forged verdict fields, or early exit cannot yield a pass.
6. Require verifier submission permissions to equal contract `allowed_changes`, worker inputs to be the inspected transfer allowlist, and output limits to fit runtime/task policy. Join grade receipts to exact task, submission, baseline/recipe, adapter, verifier, comparison/input manifest and seed identities. Only complete required feature plus preservation passes with no protocol violation earn binary one.

Structural/type validation proves shapes, bounds and ID relationships. Evidence grounding checks provenance and whether assertions follow from disclosed obligations. Semantic qualification separately requires real B health/diagnosed absence, H success, meaningful negatives per mandatory requirement, hard-coded/regression/adversarial controls, an independent valid alternative, fresh/interrupted-reset runs, and human review under §§9/17. Neither of the first two gates substitutes for the third.

## M3 handoff dependencies and operation result

Verify later against M3's reviewed API and real receipts: validated source-only overlay on clean B; bounded archive expansion and declared dependency/build policy; isolated rebuild without imported solver packages/caches or controller-side candidate/build-hook execution; no oracle or controller-store mounts; bounded input/output and externally enforced limits; attributable saved permitted source after ordinary episode limits; fresh state, kill/reap and cleanup evidence, including failure paths. Require supervisor evidence distinguishing candidate build/import/crash/resource termination from proven platform/monitor/storage/cleanup failures. Candidate-caused measured failures receive zero; infrastructure or unresolvable attribution receives no fabricated reward. Preserve the same submission and seed/manifest for outage retry.

The eventual exact service remains `GradingService.grade(task_version: ArtifactRef, submission: ArtifactRef, case_seed: int) -> OperationResult`, validated with M0 `GradeRequest`. `OperationResult` has no reward field: publish an immutable strictly validated M4-local grade receipt in its `artifacts`, with evidence/costs/reason. Successful operation execution can report a measured candidate zero; `success` is not reward one. Missing upstream capability is `blocked_dependency`; unsupported observation semantics are `unsupported_semantics`; invalid/platform failures retain their explicit disposition and unknown measurements, not invented zero costs.

Open handoff checks: actual frozen M2 contract/scenarios and discovered Click entry points; sufficient grounded variation domains and comparisons for every obligation; M2's supported proposal schema and measured generation envelope; reviewed M3 source-transfer/observation/limit/cleanup API and failure-attribution evidence. None currently establishes M4 readiness to execute. The same M4 owner must implement and qualify these joins and document its actual submission/comparison/receipt API after handoff.
