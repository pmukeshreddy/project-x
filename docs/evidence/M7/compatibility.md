## Per-turn data and loss accounting

`harbor.models.agent.rollout_detail.RolloutDetail` is an optional-key TypedDict:

```python
prompt_token_ids: list[list[int]]       # complete actual context for each turn
completion_token_ids: list[list[int]]   # sampled response for each turn
logprobs: list[list[float]]             # behavior logprob per sampled token
extra: dict[str, list[Any]]            # provider-specific, per-turn
```

Harbor `LiteLLM` requests `logprobs=True` and `extra_body.return_token_ids=True` (`llms/lite_llm.py:310–329`). It extracts completion IDs from `choices[0].provider_specific_fields['token_ids']`, prompt IDs from `response.prompt_token_ids`, and logprobs from `choices[0].logprobs.content` (`:449–505`). Crucially it can retry rejected parameters **without** token IDs (`:368–397`). `Chat._accumulate_rollout_details` independently appends only truthy fields (`chat.py:134–151`): partial or empty responses can break alignment. The training adapter must reject incomplete/empty/misaligned/nonfinite or wrong-tokenizer traces; never retokenize to invent sampled IDs/logprobs. A demo policy without exact details remains explicitly nontrainable.

Stock `build_step_wise_generator_output` emits one row per turn, with contiguous rows for each `TrajectoryID`, terminal reward only on the final row, `is_last_step=True` exactly once, all sampled completion positions masked 1 (`harbor_generator.py:126–168,203–214`). `GeneratorOutput` (`generators/base.py:36–58`) holds:

```python
prompt_token_ids, response_ids, loss_masks: list[list[int]]
rollout_logprobs: list[list[float]] | None
rewards: list[float] | list[list[float]]
trajectory_ids: list[TrajectoryID] | None
is_last_step: list[bool] | None
stop_reasons: list[str] | None
rollout_metrics: dict | None
```

The separate exact prompt for every turn is essential. `merge_stepwise_output` merges only when previous full token context is an exact prefix of the next prompt, masks newly inserted observations 0, preserves original sampled logprobs, and otherwise flushes to a separate row (`generators/utils.py:768–963`). This is a useful existing implementation, not license to reconstruct a conversation from final text. Disable merging for the first trace audit, then test equivalence before enabling; `token_mean` keeps normalization invariant to safe prefix merges. Persist original unmerged records regardless.

`convert_prompts_responses_to_batch_tensors` yields left-padded `(rows,max_total)` sequences/attention mask and right-aligned `(rows,max_response)` response indicator/reward/loss-mask/logprob tensors (`dataset/preprocess.py:90–155`). Response indicator is **not** the assistant-only loss mask. All prompt/tool/harness/padding tokens must be excluded from policy loss, ratio and KL. `validate_generator_output` checks lengths and contiguous trajectory boundaries but warns rather than rejects all-zero masks (`trainer_utils.py:695–838`); project validator must add finiteness, source/provenance, policy identity, exact template/tokenizer identity, mandatory terminal ownership, no duplicate sampled tokens, and empty-batch skip.

Despite the Harbor entrypoint/docstrings referring to truncation, actual preprocessing merely warns when `max_total > max_seq_len` and **does not truncate** (`preprocess.py:110–115`). Enforce input/output limits before each inference request and reject unexpected overlength serialization before optimizer work. Keep `enable_summarize=false`; Terminus2 does raise context-length errors without summarization (`terminus_2.py:1003–1009`). Record its terminal-output shortening and malformed-response salvage as explicit harness behavior (`:522–559,1076–1145`), including the actual subsequent prompt; these must never masquerade as sampled text.

## Synchronous four-rollout GRPO

The stock synchronous `RayPPOTrainer.train` initializes sync, resumes, syncs before collection (`trainer.py:276–287`), awaits generator (`:345–363`), computes advantages, updates, checkpoints, and awaits a new sync (`:430–492`). Use that path, not the fully async entrypoint. Stock `HarborGenerator.generate` only consumes `prompts` and `trajectory_ids`, and the loop sets task path/session/cache salt; it does not consume `input_batch.sampling_params`, `env_extras`, batch metadata, episode seeds or private case seeds (`harbor_generator.py:306–343,363–384`). Therefore the adapter must explicitly supply all those controls.

Proposed initial configuration after adapter qualification (values are explicit engineering choices, not tuned claims): four episodes, one update epoch, standard clipped surrogate epsilon low/high 0.2, `token_mean`, centered rewards without std normalization, KL-in-reward false, frozen-reference KL loss coefficient 0.001 using k3, temperature 1.0, top_p 1.0/top_k -1, no dynamic sampling/zero-variance filtering, no entropy reward, frozen reference (`update_ref_every_epoch=false`). Record any development-selected changes before main training. A nonzero KL term may produce updates for a uniform-reward group; its **task advantage** must still be exactly zero.

`RayPPOTrainer.compute_advantages_and_returns` takes terminal rows, groups by instance UID, broadcasts trajectory advantage back to all rows (`trainer.py:1128–1166`). It passes an all-ones response mask to the estimator, so setting invalid peers' loss masks to zero **does not remove their rewards from peers' baseline**. `compute_grpo_outcome_advantage` groups all scores, and for a singleton uses mean 0/std 1 (`ppo_utils.py:1287–1337`), producing a nonzero singleton reward advantage. Override with validity-aware terminal selection, per-group effective count, singleton/no-valid skip, valid-only mean (and explicit std policy), then broadcast by actual trajectory identity. Keep uniform groups in outcomes/costs, zero task advantage, and never use dynamic resampling to manufacture signal. Entire optimization batches with no eligible tokens must skip the optimizer explicitly.

A second material distinction: stock `ppo_policy_loss` uses `exp(log_probs-old_log_probs)` with the trainer's recomputed old probabilities (`ppo_utils.py:555–589`), not directly sampled behavior probabilities. `rollout_is_policy_loss` uses sampled behavior probabilities but a different calibrated hard-zero objective (`:767–807`), **not the clipped GRPO surrogate**. For the literal proposed clipped sampled-behavior ratio, register a custom policy loss through `register_policy_loss` / `PolicyLossRegistry` and `sync_registries_to_ray` (`ppo_utils.py:386–551`); keep `rollout_logprobs` required and detached, apply the clipped surrogate and existing loss normalization/masking. Alternatively any decision to retain stock regular + TIS needs a separately named, reviewed algorithm choice and measured inference/recomputed-probability differences, not an equivalence claim.

Adapter scheduling must freeze a behavior policy for the whole batch, derive distinct recorded episode seeds per repetition, use the **same private case seed for all four**, and keep the private seed/expectations out of prompts and candidate environment. Cap feasibility at 64 groups; require eight mixed groups spanning four training tasks before expansion. That gate requires real externally graded episodes. Stock APIs do not encode these project rules.

## Policy sync and checkpoint/resume

`WorkerDispatch.save_weights_for_sampler` prepares/broadcasts/wakes colocated engines, or pauses non-colocated generation around broadcast, then increments the client's local counter (`workers/worker_dispatch.py:606–652`). `RemoteInferenceClient._weight_version` starts at zero and is a monotonic local counter (`remote_inference_client.py:228–238`). Harbor's cache salt uses that counter once per batch (`harbor_generator.py:291–318`). A salt/counter is **not a worker attestation or content identity**, and no persistent policy-version ID is emitted in `GeneratorOutput`.

Add a durable checkpoint/policy digest, expected version on every request/turn/result, worker sync acknowledgments tied to that identity, stale-worker rejection and a fixed-input inference check before the next collection. On resume, derive identity from verified checkpoint manifest, not the reset counter. Keep sync endpoints and model credentials unreachable from candidate workers; a control counter cannot protect an exposed update endpoint.

FSDP strategy calls `loss.backward()`, clips gradients, skips nonfinite gradient steps, calls AdamW and scheduler (`distributed/fsdp_strategy.py:145–183,253–282`). Save/load hooks write per-rank model, optimizer, scheduler and RNG state (`:358–430,451–537`). `RayPPOTrainer.save_checkpoints` additionally saves dataloader state and `{global_step, config}`; load restores policy optimizer/scheduler and dataloader (`trainer.py:1627–1680,1694–1805`). Thus real state hooks exist.

They need stricter project wrapping: dataloader save/load errors only warn; missing cursor can restart from beginning; global-step mismatch only warns. The latest marker is written last directly, but there is no content-hashed transactional project manifest. Reference identity, consumed immutable task roster, split/sampler balance state, episode/case-seed cursor, controller RNG, feasibility counters/budget/cost ledger, policy identity and exact model/tokenizer/template revisions need explicit storage and fail-closed validation. Require optimizer state after a real nonzero-gradient update, changed trainable tensors, save/reload tensor agreement, frozen-input inference agreement and resumed next-batch equivalence. Checkpoint files from tests or a skipped update are not feature-learning evidence.

The inspected upstream `test_trainer_full_checkpointing` uses a mocked generator/dummy dataset, sets `global_step=2` before saving, and has no inference engine (`test_trainer_full_checkpointing.py:98–128,175–185`). Do not cite it as a feature update. The older `test_grpo_sp_sanity.py` references outdated trainer fields; this investigation does not propose it as a verified smoke command.

## Harbor artifact and verifier trust boundary

1. `Trial._init_artifact_handler` combines task and trial artifacts (`trial.py:675–680`); step artifacts can append. `ArtifactHandler._normalized_artifacts` unconditionally inserts the conventional source if absent (`artifact_handler.py:112–134`). On Linux this is **`/logs/artifacts`** (`models/trial/paths.py:35–38`). Empty explicit lists do not disable it.
2. Download is best effort, and mounted artifacts can bypass download entirely (`artifact_handler.py:162–217`). Source-directory transfer and exclude patterns are not positive file allowlisting. Stock artifact destination only removes root path components (`:234–256`), while `ArtifactConfig` supplies unrestricted strings (`models/task/config.py:522–529`); never accept candidate-provided transfer configuration or rely on it as archive containment validation.
3. Upload restores each explicit artifact to its **source path**, not its host destination; directories are emptied with chmod before upload (`artifact_handler.py:72–110,265–274`). Convention contents are uploaded back to target convention path. A “separate” verifier can therefore receive arbitrary candidate-produced contents unless transfer is replaced.
4. Separate mode runs a second environment, uploads these artifacts, then invokes `Verifier.verify` (`trial.py:451–517`). The image build context is task `tests/`, skip-tests-upload assumes `/tests/test.sh` already exists, and verifier executes it then parses reward files (`trial.py:575–580`; `verifier/verifier.py:91–98,133–218`). An ordinary script importing candidate code next to private expectations is still an untrusted-code-in-oracle boundary violation.
5. Trial's default Linux mount set includes agent, verifier and artifact log directories (`trial.py:838–865`); separate verifier mounts its host log directory (`:560–573`). Audit automatic log upload/download too (`:391–421`). Do not expose private bundles, cached auth, controller workspace, Docker socket or model-update controls via these paths.

Required design: controller owns comparisons/private expectations and worker orchestration; M3 worker A alone executes agent commands; freeze an allowlisted, content-hashed source submission; M3 worker B alone builds/imports/runs candidate probes; controller receives bounded inert observations and computes M4 reward. The candidate must never run/import in the trusted controller, private comparison process, or verifier image-build process. Build verifier/worker images from trusted reviewed inputs before submission exists. Replace/bypass stock automatic `ArtifactHandler` transfer and stock in-environment reward script with reviewed M3 submission transport and M4 observation/comparison flow; transfer only allowed source files, reject symlinks/hardlinks/devices/path escapes/oversize archives, and fail on extraction loss. Treat all copied source/logs as data. Separate-container availability is useful but not equivalent to this boundary.
