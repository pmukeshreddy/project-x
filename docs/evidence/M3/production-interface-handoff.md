## One concrete upstream blocker, routed to root/M0

**Bounded artifact reads are missing.** `ArtifactStore.get_bytes(ref)` and `get_artifact(ref)` call `_get`, whose `_read_file` does unbounded `stream.read()` before digest/JSON validation; raw objects are then base64-decoded. `ArtifactRef` carries no byte length. Consequently an M3 preflight cannot bound allocation from an oversized/corrupt object through the existing public read methods; checking `len(store.get_bytes(ref))` is too late.

Requested shared capability, not an existing API: explicit bounded reads with a serialized-envelope maximum checked against the opened regular file and enforced while reading, plus a decoded-byte maximum for raw objects before unbounded base64 allocation. Retain descriptor-relative/O_NOFOLLOW handling, authorization, canonical JSON, duplicate-key rejection, digest/schema checks, and a typed oversize failure. Typed recipe reads also need an envelope cap. M0 owns the exact backward-compatible method signatures and tests; M3 must consume those actual signatures after handoff. No store code was changed here. M3 will additionally enforce per-object, aggregate staged bytes, file count, expanded archive bytes and export limits. It should not duplicate private store internals to circumvent this gap.

No other **blocking shared-schema change** was found. The existing recipe has provenance inputs suitable for an explicit policy reference; module-specific validated policy/request/result records can be canonical ordinary JSON published with `put_bytes`. They do not require registration as a new M0 artifact kind. Their own decoding and visibility/ref checks remain M3's responsibility, since opaque byte publication does not inspect embedded references.

## Actual upstream surfaces and required joins

- `EnvironmentRecipe`: image digest, interpreter, `DependencyPin` tuples, nonempty `setup`/`reset` `CommandSpec` tuples, services, `ResourceLimits`, neutral repairs, locale/timezone/environment/randomness, network policy, and baseline ref. It also requires `ArtifactModel` provenance/evidence/costs. M3 will revalidate incoming instances, reject unsupported services/network, duplicate/conflicting environment or dependency declarations, unsafe paths and unapproved setup inputs, and compare the image/profile/dependency identities with the approved policy.
- `ResourceLimits`: wall seconds, **CPU seconds (a time budget, not a CPU quota rate)**, memory, pids, output bytes, disk bytes, tool calls and input/output tokens. `CommandSpec` contains only argv, working directory and command timeout. M3-local policy supplies stdin/archive caps, CPU rate plus aggregate CPU accounting/termination semantics, tmpfs allocations, lifecycle/export/cleanup deadlines and source-save policy. Effective command limits cannot increase episode/recipe limits. Token/tool accounting belongs to the caller, with M3 reporting its executions; M3 must not pretend Docker enforces token counts.
- `DependencyPin.sha256` is the raw wheel digest. `DependencyPin.artifact.sha256` and source `ArtifactRef.sha256` are **canonical store-envelope digests**, not raw-byte digests. Resolve/verify both bindings; never equate them. Store reads enforce kind/schema/visibility, while M3 independently validates raw bytes, filenames, package metadata, archive policy and aggregate bounds.
- `AuthoringSourceView(request_evidence, baseline, license_text)` admits public/authoring refs. `PullRequestIntakeResult` separates it from private `candidate`, `source_pair`, `reference`, manual-review paths and provenance label. M3 B-only discovery accepts `authoring.baseline`, revalidates its actual ref and `source-archive` kind, and receives no H/private source-pair payload in that worker.
- Controller-only `SourcePair` v2 binds candidate, baseline/reference commits and source refs. The privileged caller must resolve the real M1 result and require equality of the view's baseline, recipe baseline and pair baseline before reference/candidate use. Reference selection must equal `SourcePair.reference`; candidate source must carry its baseline plus validated change-policy binding. A source role string or a user-provided commit string is insufficient.
- M2's actual `LocalGenerationProvider.generate(request, StrictModelSubclass)` returns content/usage/cost/record and has attributable typed failure/publication recovery. It is a model provider, **not an implemented discovery-command runner**. No new M2 API is assumed. Future M2 discovery and M4 adapters can consume the proposed M3 execution surface below. Generated code remains untrusted Docker input; private comparisons stay outside every worker.

## Proposed M3-owned minimal API

These names describe the implementation surface to be finalized at dispatch, not methods that exist today. Local strict request/result models will reuse actual M0 `ArtifactRef`, `EnvironmentRecipe`, `CommandSpec`, `ResourceLimits`, `AllowedChanges`, evidence and cost types.

| Operation | Minimal responsibility and result |
| --- | --- |
| `prepare_recipe(request)` | Validate and persist the real recipe plus a versioned execution policy and source-free dependency-supply manifest. Return exact refs and preparation receipts; distinguish published recipe from successfully tested setup. |
| `open_workspace(request)` | Bind recipe/policy, initial source and raw digest, source policy, role, limits and operation ID. Persist ownership intent **before Docker create**, then container ID before start; return an opaque controller-owned handle and initial saved-source version. |
| `execute(handle, request)` | Run an argv/working-directory command with bounded ordinary stdin or explicit adapter/input refs. Enforce input, execution and terminal deadlines independently of stream EOF/client exit. Return bounded stdout/stderr, separate attach/container exit/state, termination class, measurements/costs, receipts, cleanup status and attributable saved-source ref/version. No reward or grader verdict. |
| `save_source(handle)` | Export only declared source artifacts as bounded untrusted bytes; validate paths, types, links, duplicate names, counts, expanded bytes and allowed changes in the controller. Atomically publish the valid snapshot and save receipt before advancing the durable last-saved pointer. Never extract arbitrary worker output into controller code/store paths. |
| `build_snapshot(request)` | Fresh B/H/candidate build from the exact bound source and common approved dependencies/setup. Return source-to-built-wheel/controller manifest bindings and isolated execution/import diagnostics. No H/candidate wheel enters a reusable layer. Build manifests/backends must match the actual allowed-change policy. |
| `reset(handle)` | Preserve the declared saved submission, dispose of the old owned scope, recreate the original bound source/logical state, run the recipe's concrete restoration/setup commands, and return a new handle/generation with reset receipts. A reset command's exit alone never substitutes for external teardown/recreation. |
| `close(handle)` / `recover_owned()` | Bounded removal and verified absence of the exact owned Docker scope; recover persisted incomplete attempts after controller interruption. Return clean/pending/unverified/infrastructure outcomes and partial publication recovery without executing work again. |

A durable private ownership registry under M3's ignored state directory must identify operation ID, owner token, daemon/context identity, intended container name/labels and eventual ID, exact recipe/policy/source refs, generation, deadlines, lifecycle phase, last-saved source ref/version/time, and pending publication/cleanup. Use safe paths and durable atomic state transitions. Recovery acts only on an exact matching owned identity, never unrelated label matches or a daemon-wide prune. Immutable receipts go to the existing artifact store; the registry is the controller's recoverable lifecycle index, not a replacement M6 task-admission ledger.

Each run/build/save receipt binds the exact recipe ref, policy ref/version and raw profile digest, controller-selected source ref/raw digest, dependency artifacts/raw hashes, command plus stdin/adapter identities, effective limits, operation/container identity, timestamps and implementation revision. Put the policy ref in the recipe's provenance inputs so changing seccomp, staging/import rules, save behavior or limits changes the recipe identity. Keep private source-pair joins out of authoring/public recipe provenance; retain them in separate private controller receipts. All checks are service admission checks, not trust placed in worker-reported identities.

## Ordinary limits and remaining production gates

The minimum supported source policy will explicitly expose **last-saved snapshot semantics**: persist the validated initial source before the first command; publish subsequent validated saves; every timeout/output/CPU/tool/episode limit returns the latest confirmed source ref and exact save version/time, with unsaved changes clearly identified as unavailable. Prefer a bounded current-source export when it can be completed safely; if it fails or the worker is already gone, retain the prior confirmed snapshot. Do not destroy the only confirmed submission before publishing it, invent a new successful snapshot, or convert infrastructure cleanup failure into ordinary reward zero. M7 must see the save policy so a command limit still grades attributable saved work. Any stronger freeze/export guarantee requires actual implementation evidence.

Production still must prove all five review gates through its own API: whole-lifecycle bounds, authoritative absence and persisted recovery, machine-checked denials, source preservation, and offline setup/import/source bindings. In particular, an exited Docker CLI or empty output pipes do not establish container/process-scope exit; a failed daemon request does not establish absence. Inspect and remove the owned scope even after its client exits, preserving uncertain cleanup as a typed failure.
