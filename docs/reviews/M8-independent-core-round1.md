# M8 independent checkpoint review — round 1

Coordinator review of the independent M8 owner checkpoint `35d3fcf9928942b4d5885f0c200cba04f89835c3`. Scope: new evaluation/audit models, freeze checks, statistics, actual audit service and their tests. No unchanged upstream implementation was reopened. Review is **FAIL** for the confirmed defects below. The still-unimplemented evaluation runner is a remaining deliverable, not a fabricated successful execution.

1. **P1 — two audit error denominators are wrong.** `audits/statistics.py:25,62` conditions every estimate on the verifier's decision. `accepted_among_invalid` must condition on the human finding of invalidity, and `rejected_among_valid` on human validity; unresolved/invalid-environment observations need separate accounting. The existing test encodes the implementation's wrong denominators. A direct CPU probe using five equal-probability samples `(accepted,invalid), (rejected,invalid), (accepted,valid), (accepted,valid), (rejected,valid)` returned `1/3, null, 1/2`; the specified rates are `1/3, 1/2, 1/3`. Add hand-derived unequal-weight and unresolved examples without mixing source audits into patch estimates.

2. **P1 — true rejected sources cannot be audited.** `audits/models.py:16` requires every selection to be a run, while `service.py:68` requires a completed run with a RolloutRecord and grade. A candidate rejected before construction has none of these. Merely labeling an ordinary rollout `rejected_source` satisfies the manifest but does not implement the required rejected-source audit. Add a distinct authenticated candidate/source path bound to actual M1/M6 retained disposition and source evidence, with separate units/denominators and an actual source-adjudication payload. Keep the patch audit path exact.

3. **P1 — the population estimate does not authenticate its frame or completion.** The service never reads `population_frame`, checks the selected repository family against the task/source, or derives/verifies inclusion probabilities. `audit(run_ids)` accepts any chosen subset of the frozen selections and immediately computes population estimates for that subset. Thus selected failures can be omitted without being represented as unresolved. Implement a frozen, typed source/patch frame and reproducible stratified selection; bind family/status/failure-category and probabilities to the actual frame. Report the complete selected sample, retaining unavailable adjudications explicitly, before making weighted population estimates. Targeted findings remain separate.

4. **P1 — an infrastructure outcome is automatically called a verifier defect.** `audits/service.py:209` quarantines a verifier whenever its outcome is `invalid` and a human judges the submitted patch valid. A correct patch whose worker suffered an infrastructure failure is not evidence of a false rejection. Separate patch-validity findings from invalid-environment findings, and require an adjudicated checker decision defect for checker quarantine. Source defects likewise need their actual source/version subject, not a fabricated verifier.

5. **P2 — accepted best-of-k input silently returns a different metric.** A valid frozen `best_of_k` study with two episodes, one failure followed by success on each task, returned `pass_at_1/D/all_assigned=0.5` over four episodes. Its best-of-2 rate is `1.0` over two task/seed assignments. Implement the explicit declared metric and its assigned/valid denominator rules, with paired cases and distinct naming. Do not silently pool episodes under pass@1.

6. **P2 — policy seeds are confused with training replicates.** `evaluation/statistics.py:137` omits the training-variability limitation as soon as two inference policy seeds are present. Each arm currently still has one checkpoint and no independently trained replicate dimension. Keep that limitation explicit until real independently trained replicates are represented; policy-sampling seeds do not estimate training variability.
