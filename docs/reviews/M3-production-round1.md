## Finding

**P2 — close overwrites a successful concurrent save with a stale workspace record.** [runtime.py:283](../../src/feature_rl/environments/runtime.py#L283) reads `value` before acquiring the state lock at line 284. It then writes that entire stale record, including `saved` and `generation`, at line 285. The command save at [runtime.py:263](../../src/feature_rl/environments/runtime.py#L263) is correctly protected by the session lock, but that does not protect the earlier close read. `reset` has the same read-before-lock pattern at lines 277–279; the reproduced failure is specifically close.

The bounded [diagnostic](../evidence/M3/review-round1/close_race.py) pauses close immediately after its real `workspace()` read, runs one actual Docker development command to edit synthetic `src/click/__init__.py` from `x=1` to `x=42`, then resumes close. No application behavior, save logic, state writer, lock, Docker engine or cleanup method is mocked. The synchronization wrapper only selects a possible thread schedule.

Observed sequence from [close-race-result.json](../evidence/M3/review-round1/close-race-result.json):

1. Close reads source version 0 / generation 0, artifact `0268837862eab8bbd900e4ed8efd730ce961e58e00e4f1b576fb301746c9368a`, saved at `2026-09-19T19:44:43.620545+00:00`.
2. Development returns `completed`, `save_status=saved`, `cleanup_verified=true`, source version 1, artifact `12047b2f849c48beb035d93d21c882d39c623deb977f7fab4d172fb65f4fca7c`, saved at `2026-09-19T19:44:46.507873+00:00`. Its real save increments the workspace generation to 1.
3. Close resumes, returns version 0 and durably writes `closed=true`, version 0, **generation 0**. The already acknowledged version 1 remains in CAS/evidence but is no longer the closed workspace's submission.

There is no serial ordering that explains both successes: close first should make later execution fail admission; execution first should make close return the new saved source. This can grade stale code or lose a learner's acknowledged final edit. It is a correctness defect, not merely a request for more concurrency stress tests. Protect the read/check/write transition with the same operation lock, or revalidate/reload under that lock before writing; apply the invariant consistently to close/reset. A focused regression must preserve the latest confirmed saved source and monotonically increasing generation, or explicitly reject the overlapping operation.
