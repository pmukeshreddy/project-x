## Findings

### P0 — Repository-local Git configuration can execute an arbitrary host command

Locations: `src/feature_rl/history/git.py:69-78` and `:178-183`; contradicted interface claim at `docs/interfaces-M1.md:28`.

`GitHistory` disables hooks and global/system configuration, but it still loads repository-local configuration. `_patch_digest` runs `git diff --binary --full-index` without `--no-ext-diff` or equivalent isolation. Git therefore honors a local `diff.external` command while reconstructing B/H inside the trusted controller.

A narrow reproduction initialized an inert local repository, configured `diff.external` to a helper that created a marker, and called `GitHistory.reconstruct(..., integration="linear")`. The marker was created. This is direct host code execution through source-controlled intake state, contrary to the brief's requirement that Git be used only as data tooling and that historical scripts/hooks never run on the host. Disabling hooks does not disable diff drivers.

Required correction: make every Git invocation independent of untrusted repository configuration and explicitly disable external diff/text-conversion execution. Audit every invoked Git subcommand for configuration-driven helpers, filters, hooks, pagers, remote helpers, and lazy fetching. Add a regression test with a hostile local Git config that proves no helper executes while reconstruction, path enumeration, object lookup, and archiving still work or fail closed.

### P1 — Read-only Git inspection can lazily fetch and mutate a partial clone

Locations: `src/feature_rl/history/git.py:81-90`, `:92-141`, and `:269-271`; interface claim at `docs/interfaces-M1.md:28`.

The subprocess environment does not disable promisor-object lazy fetching. A narrow reproduction created a blob-filtered promisor bare clone, counted its object files, and called `GitHistory.archive_tree`. Git fetched the missing blob through the configured remote: the object-file count increased from 8 to 12. Thus an operation documented as reading an existing object database can perform network acquisition and write new objects. The fetch also bypasses `BoundedHttpFetcher`, the source manifest, its byte cap, and its archived retrieval provenance; an output cap does not bound the size or duration of the preceding object transfer.

The real `.feature-rl/research/M1/git/click.git` is a promisor partial clone. The coordinator's current-cache audit found no repository-local `diff.*`, `filter.*`, `core.fsmonitor`, or `include.*` entries, which bounds P0 for that cache at audit time. It does not disable or disprove lazy fetching and is not historical proof of how earlier commands ran.

Required correction: disable lazy fetches for all inspection commands, preflight that every required commit/tree/blob is locally present, and fail explicitly on a missing object. Fetching must remain a separate bounded, archived acquisition step. Test a deliberately incomplete promisor repository and assert both explicit failure and an unchanged object database.

### P1 — Historical-request admission and cutoff chronology are not enforced

Locations: `src/feature_rl/intake/github.py:102-124`, `:182-210`, `:431-469`, and result fields at `:127-145`.

`PullRequestIntakeSpec` accepts `historical_request` solely from a caller-supplied label. The loader hard-codes issue/PR/comment edit history as unavailable, yet ingestion never requires defensible historical body evidence for that label. It also does not require the admissible cutoff to precede integration/retrieval/recording, require `recorded_at` to follow source retrieval, or require the visible issue to exist by the cutoff. It always emits the currently retrieved issue body. The caveat always says reconstructed specification, even when the accepted label says historical request.

A narrow constructor reproduction accepted `provenance_label="historical_request"`, `admissible_cutoff=2099-01-01`, and `recorded_at=2020-01-01`. The same values reach ingestion unchanged. A caller can therefore expose postimplementation/current text as historical evidence and create internally contradictory timestamps. The label is also absent from `PullRequestIntakeResult`, `CandidateRecord`, and `SourcePair`; it survives only inside the authoring bytes and a private proof blob, despite the specification requiring the provenance label in every result.

The preserved Click run itself correctly uses `reconstructed_specification` and discloses unavailable body history, so this finding does not relabel that specific artifact. It blocks relying on the production admission rule for later candidates.

Required correction: derive or validate provenance from archived edit/cutoff evidence, reject impossible chronology, and force reconstructed provenance whenever a defensible historical body revision is unavailable. Preserve the validated label in every durable/result interface, proposing the required shared-schema extension rather than burying it only in opaque evidence bytes. Add positive historical and reconstructed cases plus edited/post-cutoff/contradictory-time negatives.

### P1 — Squash reconstruction accepts a disconnected source history

Location: `src/feature_rl/history/git.py:208-218`; connected intake reliance at `src/feature_rl/intake/github.py:237-246`.

For squash integration, the implementation checks that the declared source-head tree equals H's tree, then enumerates commits not reachable from B. It never proves that B is an ancestor or merge base of the source chain. A narrow reproduction created ordinary B and H commits, then a parentless orphan commit with H's tree. `reconstruct(H, integration="squash", source_head=orphan)` accepted the disconnected commit as the implementation history.

Equal final trees bind content but do not establish that the claimed PR source chain was integrated from B. This can associate unrelated/copied history with a candidate and weakens both provenance and lineage evidence. The real Click evidence independently shows that its source chain starts at B, so the recorded Click pair remains credible; the production invariant is missing.

Required correction: prove and record the appropriate merge base/ancestry relationship for the source chain, reject disconnected or ambiguous source histories, and add the orphan-but-equal-tree regression case.

### P1 — Connected rebase intake uses source SHAs as the integrated span

Locations: `src/feature_rl/intake/github.py:230-246` and `src/feature_rl/history/git.py:219-233`; inadequate coverage at `tests/test_history.py:101-130`.

For `rebase`, connected intake passes the PR commits response directly as `implementation_commits`. `GitHistory.reconstruct` then requires the last one to equal `merge_commit_sha`/H and each declared commit to be the one-parent integrated chain. A real rebase rewrites the source commits onto the target, so the PR-head/source SHAs and integrated SHAs differ. The production path will reject an ordinary rewritten rebase rather than recover its contiguous integrated span. The existing parametrized test creates commits directly on one line and calls `GitHistory` with those same SHAs; it exercises linear ancestry under two labels, not source-to-rebased identity mapping.

Required correction: recover the integrated post-rewrite span from target ancestry and bind it to the archived source patch/commit evidence, rejecting ambiguity or interleaving. Add a connected fixture with distinct source and rebased commit IDs plus ambiguous/interleaved negatives.

### P1 — The published license text is not bound to the verified Git blob

Locations: `src/feature_rl/intake/github.py:258-271` and `:388-392`.

Intake verifies only that the license API's claimed object ID equals B's `LICENSE.txt` object. It separately loads arbitrary cached bytes named by `license_text_name`, archives them as authoring-visible, and sets `LicenseRecord.status="verified"` without comparing those bytes to the Git blob or even to the API response content. A valid manifest containing unrelated license text therefore yields a verified license record and exposes the unrelated text to the author.

The real Click investigation independently records matching Git and raw-license content, so its factual license conclusion is supportable. The production evidence chain does not enforce that relationship.

Required correction: read or hash the actual B license blob under a bounded Git object operation and compare it byte-for-byte/object-ID-for-object-ID with the archived text before marking the license verified. Verify the relevant H license state or explicitly scope the decision to B. Add mismatched-text and changed-license negatives.

### P2 — HTTP bounds do not cover redirects or total elapsed time

Location: `src/feature_rl/intake/sources.py:91-153`; coverage at `tests/test_intake.py:30-64`.

The fetcher validates only the input URL. `urllib` may follow a redirect to a different host or a downgraded/nonpublic target, while the returned `FetchedSource.url` still records the original HTTPS URL. The code does not validate the final response URL or archive the redirect chain. Its timeout is passed to `urlopen` as an I/O timeout, not enforced as a total wall-clock deadline; a response that continues making progress can exceed the declared operation deadline. The tests inject direct size and immediate-timeout failures and do not exercise redirects or a trickling response.

Required correction: enforce the source policy on every redirect/final URL, preserve the redirect chain as source evidence, and use a monotonic whole-operation deadline while streaming under the byte cap. Add HTTPS-to-disallowed-target and slow-progress cases.
