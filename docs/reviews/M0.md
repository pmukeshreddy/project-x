## Findings

### P1 — Reference solutions can be marked author-visible

Locations: `src/feature_rl/contracts/models.py:348` and `:575`; relevant access policy `src/feature_rl/artifacts/store.py:42` and exposure checks `:152`.

`SourcePair.reference` and `TaskBundle.reference_solution` reject only `PUBLIC`. Both accept `AUTHORING`. An author-role store is explicitly allowed to read authoring objects, and a private SourcePair/TaskBundle receives no nested-reference exposure restriction. Consequently a producer can store H as authoring bytes and create a fully valid private SourcePair/TaskBundle that points to it; the author capability can then read the H bytes. Keeping the containing manifest private does not repair the reference object's access policy.

Focused reproduction changed the complete fixtures' reference visibility to `authoring`; both validators accepted it. This conflicts with spec §6.1's B-only initial drafting boundary and the M0 interface's statement that H is private and authoring receives B separately. This is a known visibility-classification hole, distinct from downstream inspection of arbitrary byte contents.

Required correction: explicitly restrict reference-solution visibility to the approved privileged classes, including rejection of `AUTHORING`, consistently in both artifacts. Add negative schema tests and a focused role/store test showing reference solutions cannot be published as author-readable through these contracts. If a privileged control-authoring service needs H, give that service an appropriate separate capability rather than granting the ordinary author role access.

### P1 — A declared invalid trajectory can be training-eligible

Location: `src/feature_rl/contracts/models.py:668` (especially `:675–683`).

`honest_rollout` excludes invalid measurements by disposition, but never reconciles `stopping_reason` with training eligibility. A record with `stopping_reason="invalid_trajectory"`, `disposition="success"`, reward 1, aligned token arrays, matching policy version, and `training_eligible=true` is accepted. The same gap permits the infrastructure-failure stopping reason to coexist with those claims.

The focused reproducer accepted the invalid-trajectory case. This is a contradiction inside one record, requiring neither artifact dereferencing nor authenticity assessment. A learner filtering on the shared `training_eligible` flag could optimize on a trace already declared corrupt. Spec §11 explicitly excludes unexpected token/context corruption from valid trajectories, and §17 requires rejection of corrupted trajectories. Merely having correctly sized arrays cannot rehabilitate that declared failure.

Required correction: reject training eligibility for invalid-trajectory and infrastructure-failure stops, and define/enforce coherent stop/disposition combinations. Preserve the distinction between a source artifact that can still be graded and a trace that is unusable for optimization. Add focused negative tests; valid candidate failures and ordinary limit stops must remain representable.

### P2 — Evaluation success permits no measured result

Location: `src/feature_rl/contracts/models.py:755–759`; nullable metric fields at `:715–729`.

`EvaluationReport.successful_report` checks only that the trial and metric tuples are nonempty. It accepts `disposition="success"` when the sole trial is `blocked_dependency`, has no rollout and `resolved=null`, and the sole metric has `sample_size=0` with estimate/lower/upper all null. The focused reproducer accepted exactly this state. The error message promises measured metrics, but the predicate does not enforce them.

Unknown metrics are a necessary honest representation for blocked/provisional reports. Promoting a report containing no measured outcome to success violates the no-missing-evidence-success constraint and weakens the explicit evaluation result boundary in §§10, 12 and 17. This finding does not require M0 to implement M8's trial-accounting, pairing, or uncertainty algorithms.

Required correction: keep unmeasured reports nonaccepted; require an actual measured result for successful reports and reject locally contradictory trial outcomes. Do not require all trials to be valid: unresolved infrastructure trials must remain reportable under M8's explicit accounting rule. Add the zero-measurement regression case without replacing the later full-denominator gate.
