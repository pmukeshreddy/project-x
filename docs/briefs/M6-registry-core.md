Use private slice-specific test databases/stores; do not open or mutate M2's working state. Focused tests only while another product owner is active.

Use actual M0 `ArtifactRef`, `OperationResult`, `CostRecord`, dispositions and canonical serialization. Persist validated immutable artifact identities and explicit input/output dependency edges; verify referenced bytes through bounded M0 reads instead of trusting caller-made metadata. Enforce typed operations and legal job/attempt transitions, content-derived idempotent job identity, bounded queue/backpressure, explicit owner/claim handling and attempt limits. Duplicate completion cannot mint another output, reward or cost observation. Keep attempts and incurred costs distinct from unique outputs. Unknown cost fields remain unknown; failures and abandoned/interrupted attempts stay visible.

Build the SQLite authoritative event/outbox/index design supported by the preflight, with a verified append-only JSONL projection, actual recovery after partial append/lost acknowledgment and corruption rejection. Do not promise a cross-service transaction or physical power-loss behavior from a process-crash test. Event IDs/order and semantic duplicate keys must prevent omitted or duplicated costs on replay. Bound event and read sizes; reject malicious paths/links or an unexpected state-directory shape. Use actual filesystem durability and database concurrency controls with explicit failure behavior.

Provide an explicit reconciliation surface for already-published upstream artifact/attempt/cost receipts. Existing M2 `GenerationCallRecord` and `GenerationProviderError` publish internally before returning, so a future factory wrapper must be able to register those actual identities idempotently after a crash or publication retry. Registry code may depend on shared M0 values and raw receipt references; it must not import an imagined future authoring service or manufacture completed observations for lost work. State exactly what the caller must supply to reconcile a real upstream operation.

Implement dependency invalidation/quarantine and affected-descendant/run/checkpoint tracing over exact immutable references. Changed inputs produce new identities; old frozen records are preserved. A quarantined input must remain visible through descendants, and unquarantine/repair must not silently rewrite the record of previously consumed data. This core does not approve a task; actual M5/M6 lifecycle admission wiring comes later.

Meaningful acceptance cases: malformed/tampered artifacts; bounded size and path/link refusal; duplicate/replayed job/attempt/observation identities; queue limits; competing claims; crash between operation/index/outbox/projection publication; partial JSONL tail/lost acknowledgment; corrupted event and projection mismatch; cost observations that arrive before or after finalization; unknown versus measured-zero costs; stale completion; dependency cycles/drift; quarantine descendant tracing. Use real SQLite/filesystem/process diagnostics for durability/concurrency claims, clearly labeled synthetic inputs. No claim of successful feature construction, qualification or training from these tests.

Publish exact small APIs with typed arguments, outputs and recovery examples for later M2/M5/M6/M7/M8 integration. Report complete scoped code, actually executed checks and limits, exact UTC/command/status/source hashes. Commit only owned paths and return FINAL for independent review. This slice is not full M6 completion, and no placeholder public factory operation should be added to pretend otherwise.
