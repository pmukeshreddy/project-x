# M2 provider implementation report

The actual local authoring-provider slice is implemented under `src/feature_rl/generation`. It pins and verifies the approved MLX/model/dependency/platform closure, passes only declared attributable context into a fresh offline subprocess, enforces the native emitted-token limit plus external process bounds, rejects truncation and protocol drift, and retains complete immutable success/failure archives. Initial authoring remains limited to request/B/public checks. The later checker stage accepts a frozen contract and scenario plan plus explicit attributable B/public-check data without exposing H to the first draft.

Risk-based tests cover actual strict serialization, stage/visibility/reference gates, placeholder and duplicate IDs, qualified versus larger-unqualified token profiles, model-file tampering and extra files, platform/dependency drift, missing manifests, deadline/output termination and cleanup, response-envelope validation, unknown tool events, truncation, missing selected-model scores, exact input token IDs, explicit absence of behavior logprobs, malformed JSON, retained partial failure usage/cost, resource termination, HOME/cache handling, and complete archive receipts. Final verification passed all 171 tests.

`docs/evidence/M2/provider-v2-verification.json` binds those focused and full test results to exact raw outputs and a seven-file product hash inventory before commit. It does not claim a committed source revision; coordinator verification will add that binding after review.

The production-boundary preflight rejected a 381-token fully templated request against a 16-token input cap before model loading. The structured smoke accepted 383 input tokens, emitted 83 tokens under the 128-token hard emitted cap, stopped without truncation, returned the strict BLUE/nonce object, and retained raw events, provenance, usage, resource measurements, partial cost, and artifact references. A subsequent source-grounded correction renamed the recorded output scores, made behavior logprobs explicitly unavailable, added exact input token IDs, preserved HOME, and retained partial failed-call usage. The two-call evidence bound prevented another inference, so the checked smoke proves the model/resource/schema path but predates the final event-field and environment correction. See `docs/evidence/M2/production-provider-smoke.md` for the exact limitation.

This remains a partial M2 delivery. It does not author or freeze the real Click requirement contract, scenario plan, checker, reward, or experiment. Larger production envelopes remain explicitly unqualified on this host and require their own bounded measurement before a construction batch.
