# M2 provider implementation report

The local authoring-provider slice is implemented under `src/feature_rl/generation`. Fix round 4 addresses the two P2 findings in `docs/reviews/M2-provider-round3.md` while preserving the independently closed identifier/recovery boundary. Supported core-schema-only Literal outputs now return the exact validator's selected result without a second branch pass. Raw integer and float alternatives in scalar unions, nested scalar unions, Boolean/model unions and patterned mappings therefore retain their actual Python and serialized JSON types. JSON string transport for string-enum-valued Literals remains valid. M2 request/response/prompt identities remain bounded to 128 ASCII characters across requests, events, attempts and call records, with public-boundary revalidation for unchecked model copies/construction. Initial authoring remains limited to request/B/public checks. The later checker stage accepts a frozen contract and scenario plan plus explicit attributable B/public-check data without exposing H to the first draft.

The supported subset is explicit. Before, wrap and plain validators refuse before backend verification. Unions combined with after callbacks, defaults or post-init hooks also refuse because inert branch selection cannot preserve fallback semantics. Unknown core forms, custom initialization, dataclass and call forms fail at the same pre-execution boundary. Non-union after/default/post-init lifecycle behavior still runs exactly once on the original canonical JSON, including callbacks that inspect JSON validation mode. Tests cover the reviewer scalar-union, nested-container, post-init-union and before-field cases; an additional wrap-validator and definition-reference case; replay of an unsupported-schema publication failure without execution; and actual synthetic M0 `RequirementContract` and `ScenarioPlan` JSON transport. Prior Boolean/model unions, patterned mappings, enum/tuple/UTC handling and R2 identity/recovery cases remain covered. The final focused suite passes 79 tests and the affected full suite passes 234 tests. Exact commands, exit statuses and mechanical file/log identities are recorded in `docs/evidence/M2/provider-v3-fixround4-verification.json`.

All earlier provider verification receipts remain immutable. The fix-round 4 receipt separately binds current source/test/document bytes and raw test logs before commit and does not claim a committed product revision. Coordinator verification will add the committed current-source native binding only after independent re-review.

The preserved revision-1 production smoke and rejection receipts are unchanged and are not evidence for protocol v3. No inference occurred in any provider fix round. A separately declared coordinator run after review must bind and exercise the committed current protocol with an actual archived source.

This remains a partial M2 delivery. It does not author or freeze the real Click requirement contract, scenario plan, checker, reward, or experiment. Larger production envelopes remain explicitly unqualified on this host and require their own bounded measurement before a construction batch.
