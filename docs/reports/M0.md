## Implemented

- Eleven strict, frozen version-one Pydantic artifacts, with explicit nested source/license/commit/requirement/scenario/runtime/checker/control/solver-view/qualification/token/training/evaluation/audit records. All required properties reject omission, including nullable measurements. No general-purpose payload dictionary replaces a core schema.
- Enums for role, visibility, partition, disposition, task state, actor type and stop reason; explicit operation requests and shared policy/resource/training/evaluation configuration.
- UTC evidence receipts with producer, command, exact revision, scope, exit status and nonempty artifact evidence. Successful operations require outputs and a successful producer receipt. Qualification cannot claim success with missing or failed gates or unit-only integration evidence.
- Explicit unknown/partial/measured cost records. Nonfinite numbers, bool-as-int counters/rewards, unknown fields, invalid digests and ungrounded mandatory requirements are rejected.
- Human review only accepts actor type human, requires identity/subject/evidence/attestation, and binds qualification approval to the task digest. Authentication remains an external M5 gate; this record does not authenticate a person.
- Role-aware content-addressed store with exact requested four methods. Canonical UTF-8 JSON and opaque base64 byte payloads share an immutable envelope. Identity binds kind, version, visibility, encoding and payload. Reads verify all metadata, content hashes, canonical form and typed schema.
- Atomic exclusive temporary writes, fsync, create-if-absent publication, exact duplicate comparison, path descriptor traversal, symlink refusal and nonregular-file refusal. Corrupt existing objects are never overwritten. A crash leaves only ignored temporary files until retry succeeds.
- Exact schemas/examples/API rules in `docs/interfaces.md` and `docs/evidence/M0/{schemas,examples}.json`. Examples are exclusively synthetic unit diagnostics.
- Pinned Python package dependencies after querying actual PyPI metadata. Runtime Pydantic 2.13.5, test pytest 9.1.1, build hatchling 1.32.3; transitive versions in `uv.lock`.

## Material boundaries / concerns for review

- Store roles are trusted service capabilities, not authenticated identities or an OS sandbox. Untrusted workers must never access the store directory. Visibility checks cannot infer whether arbitrary raw bytes contain secrets; producers and export inspection are accountable for classification.
- Schema-valid refs are not automatically dereferenced at construction. M1–M8 services must resolve related artifacts, check actual lineage/partition/requirement joins, authenticate receipts, enforce full control coverage and validate empirical gates before admission. Qualification report success is structurally gated but its facts cannot be established from JSON alone.
- Storage requires a POSIX filesystem with directory descriptors, hardlinks and fsync. Legitimate platform symlink aliases must be resolved by the trusted caller. Crash-orphan `.pending-*` files are ignored, retained and not automatically deleted.
- The store does not mutate committed files in place. Hardlinked existing files are still hash-checked; no hardlink is followed for writing. The host OS/account remains trusted.
- Declared compatibility is Python >=3.11; executed interpreter compatibility is 3.13.7 only.
- This host assigns UF_HIDDEN to editable-install `.pth` files, which Python 3.13 ignores. Use explicit `PYTHONPATH=src` for development. Wheel import was independently verified without this workaround. No filesystem permissions/configuration were changed.
- `ModelIdentity.tokenizer_digest` is required nullable for honest nontrainable CLI/API episodes; training eligibility rejects null and missing/mismatched token evidence. No training stack is pinned by this module.

Both prohibit training eligibility and retain null reward. Saved submissions remain available for separate grading. Candidate failures, malformed actions and token/tool/time limit failures remain valid zero-reward training examples when their traces are otherwise valid; they cannot claim reward 1. Existing exact-policy regression now explicitly uses a submitted episode so it continues testing policy mismatch rather than incidentally failing on stop status.

Success requires a measured boolean outcome and rollout; candidate rejection requires false; invalid, blocked, provisional and unsupported outcomes require null. EvaluationReport success requires at least one measured trial and at least one positive-sample nonnull metric. Invalid trials remain reportable alongside measured results, and all-unknown provisional reports remain valid. Full rosters, denominators and metric authenticity remain M8 gates.
