# Candidate-specific released-task resolution

`ReleasedTaskResolver` dispatches frozen candidate-specific M5 policies through explicitly supplied actual `TaskLifecycle` profiles. Profiles bind supported lifecycle, M5, grader, runtime and builder revisions plus the current externally administered human verifier. The read uses existing `Registry.trace(Q).jobs` to find one selected release result, resolves its canonical configuration and policy, and calls the concrete M5 service and reviewed lifecycle chain. Every read rechecks current admission, quarantine and human revocation. Unsupported or ambiguous version profiles fail closed.

The resolver exposes `store`, `registry`, `configuration`, `revision` and `resolve_released(task_ref) -> TaskBundle` for actual M7/M8 consumers. Its opaque configuration explicitly depends on each trusted profile configuration. Consequently quarantining any configured profile conservatively blocks this resolver; a replacement resolver configuration can remove an obsolete profile. No task policy chooses Python code, enrollment, callbacks or a service revision absent from these profiles. A runner with one package builder still rejects tasks built by an unsupported builder revision.
