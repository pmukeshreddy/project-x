# M6 actual authoring, repair history and retained Click accounting

The new Factory boundary invokes the actual M2 contract/scenario and M4
checker/control services, with one Registry attempt per provider call and exact
archive/cost reconciliation. It does not call a model in this verification phase.
The CPU diagnostics use labeled deterministic process/backend doubles around the
real provider protocol, schemas, finalizers and Registry.

## Frozen scope and accounting

`AuthoringSettings` freezes candidate membership, candidate/batch resource
reservations, calibration refs, backend, producer revisions and evidence scope.
An immutable frontier binds those settings to source disposition, SourcePair and
M3 recipe/policy before dispatch. A same-batch lock serializes admission and
execution; durable use is reconstructed from actual Registry jobs. No additional
cost ledger or provider index exists. Reservations count the full per-call token,
wall, CPU and command ceilings even after failure; larger measured amounts raise
the charge. The memory cap is the serialized peak. M2's polling and CPU hard-limit
guard remain the actual enforcement boundary; this is not a hard bound on all
controller/storage overhead or power-loss behavior.

Null currency caps explicitly declare unpriced local compute. Incurred USD and
unmeasured controller/storage allocation stay null. Monetary comparison
verification is unavailable. Finite USD caps reject before another provider call;
there is no fabricated zero or price-meter implementation.

The stage map is contract/authoring, scenario/scenarios, and checker + controls +
alternative/verifier. At most two repairs per stage and four per candidate include
known M3 neutral repairs. A renamed request/control cannot reset this allowance.
The first bounded semantic control plan is immutable. All initial roles and
repairs remain separately attributable.

Callbacks publish an unknown attempt before provider execution and progressively
retain its request/retrieval/schema/options/provenance/events/usage/cost/status
closure. A frozen outer receipt must match selected generation accounting and the
selected previous lane journal chain before it can write artifacts or observations.
The new retained-payload mutation regressions cover both joins. An already selected
exact receipt replays without changing its cost snapshot. Historical completed
readback remains distinct from current usability/quarantine checks.

## History consumed by construction

Construction V2 freezes the history ref before actual TaskBuilder work. Existing
V1 canonical request bytes and recovery stay unchanged. The complete branch
requires the final contract, scenario and verifier to be selected terminal author
outputs and each verifier control to match an actual terminal M4 control record.
The supported order authors controls before the final checker. Later unverified
attachment/derivation refs do not become complete merely because their payload
looks plausible.

Repairs form an actual chronological chain per shared stage. The history retains
all initial evidence, provider journals, selected requests/results and original
cost records. “Complete” is confined to the explicit pre-dispatch controller scope;
it does not claim absence of earlier outside work. Externally supplied inputs and
retained imports remain incomplete. Qualification still enforces actual semantic,
independence, history and current human gates; an authored artifact is not an
accepted task.

## Real retained Click import

`docs/evidence/M6/authoring/import_click.py` copied and hash-verified the necessary
original M1/M2 artifacts into new ignored
`.feature-rl/research/M6/retained-click-authoring-v1` state. It validated and
selected all three original rejected provider journals, including their complete
archived requests/costs/status records, through `Factory.import_rejected_authoring`.
The original stores were not modified. The diagnostic guard disallows any new
provider execution. The final receipt records exact observed source hashes and
original envelope hashes; later unrelated coordinator revisions are not asserted
to be the tested bytes.

The original journals lack the later `semantic_request_sha256` field. Import
derives that identity from the exact archived request instead of rewriting history.
It reconstructs inert finalization *scope metadata* from the retained request,
discovery and pinned driver; it does not claim those fields were an originally
saved finalizer-input record and does not call that finalizer.

All three calls remain rejected. Known original generation totals are 20,808 input
tokens, 6,636 output tokens, about 324.656 wall seconds and 122.702 CPU seconds;
USD, GPU time and other unmeasured allocations remain unknown. Known repairs remain
one environment repair plus two contract repairs: three of four candidate repairs,
with the contract stage exhausted. The source CandidateRecord separately remains
provisional for mixed-purpose scope review. Neither that unresolved source gate
nor malformed contract failure is turned into approval, qualification or BUILT T0.
