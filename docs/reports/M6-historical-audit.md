# Explicit Registry scope for historical audits

Root's M8 integration review found that an audit could apply a verifier/source quarantine and then fail to complete its report because the report and frozen inputs depended on that subject. Already-quarantined historical source rows likewise could not acquire an audit claim. `Registry.historical_audit_configuration(configuration, subjects=..., protected=...)` now freezes a narrow scope for those historical reads and report publication.

The returned private configuration wraps the actual original audit configuration and two exact reference groups. Three reserved artifact kinds have canonical, bounded, strictly validated intrinsic dependencies; callers cannot add undeclared dependencies to widen their meaning. Only Registry jobs with `operation='audit'` and this configuration may ignore active notices whose **root** is within the declared subjects' historical dependency closure. Explicit protected refs, original configuration, scope/group records and new output roots remain subject to quarantine. Current envelope, payload, signature, sampling instructions and selection/configuration refs must be explicitly protected by M8. Protecting their entire transitive closure would incorrectly re-block their historical subjects, so this protection applies to the explicit current refs. Artifact integrity, bytes, ownership, bounds, accounting, external SSH trust and M8 semantic checks are never skipped.

Normal `assert_usable`, construct, run, train and evaluate checks are unchanged. An audit report may be a readable historical result while remaining quarantined for ordinary consumers. Applying an actual quarantine remains a separate durable operation; the Registry does not invent findings or claim that unapplied notices succeeded. M8 must bind the applied notice in its frozen report and recover that publication without reusing a new human decision.

No JobSpec, JobRecord, event shape, table or existing identity changed. New scope artifacts use the existing immutable artifact records and append-only event protocol. Old jobs replay to the same bytes. The scope is frozen before enqueue and cannot be retrofitted into an existing job; new configurations imply new job identities.

**37 focused CPU checks passed in 8.47 seconds**: fifteen scoped audit checks and twenty-two affected core Registry checks. [Receipt/source hashes](../evidence/M6/historical-audit/receipt.json), [raw output](../evidence/M6/historical-audit/focused.txt). Checks include quarantine applied before/after claim, subject dependencies, protected precedence, normal-operation denial, newly quarantined output denial, old identity replay, malformed/widened scope refusal, and an injected JSONL projection failure after the actual SQLite completion commit. Recovery preserved the applied notice and selected report. These are explicitly synthetic bookkeeping observations, not human approval or power-loss guarantees; no native/model/Docker work occurred.
