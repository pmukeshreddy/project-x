## Delivered behavior

The runtime consumes reviewed M0 bounded CAS reads, actual M1 source-pair joins and the approved six dependency wheels. It constructs and verifies a real pinned `EnvironmentRecipe`, persists source snapshots and owned container intent before create, validates effective Docker controls, runs bounded offline build/development/installed-wheel commands, captures allowed source changes as inert bytes, and verifies cleanup/recovery. All historical/candidate/build-hook execution stays in Docker. Source and wheel bytes are independently joined by controller hashes and file maps; imports reported inside workers are diagnostic observations rather than trusted proofs.

Development commands use the current source tree and do not require a successful candidate build. Tests demonstrate editing/importing in one command, saving a syntax error, and repairing it in a subsequent command. The separate installed-wheel path requires an exact successful snapshot build and starts in a fresh worker after destroying the build container. Reset restores the initial filesystem snapshot; dependency/process/cache state is never silently preserved. Local services are explicitly unsupported.

The default hard boundary has a read-only root; nonroot UID/GID65534; cap-drop ALL; no-new-privileges; explicit pinned seccomp; private PID/IPC/cgroup/network namespaces; no host binds; no exec-capable writable mount; 0.5 CPU rate, 512 MiB memory/no swap, 64 pids and 128 MiB total tmpfs. Ordinary output, source export, staging and control diagnostics have distinct explicit bounded caps. Nonblocking stdin/outputs and command deadlines do not confuse EOF or client exit with process termination. CPU-time budget enforcement is a sampled external monitor, with possible sampling/control overshoot disclosed, separate from the kernel rate quota. Kernel OOM events are recorded independently of exec exit code.

The saved-source policy is explicitly **last confirmed**, with source version/time and workspace generation. Capture has a bounded interval and does not claim an atomic filesystem instant. On ordinary limits, invalid/unavailable capture or interruption, the exact prior saved source remains available. Deleted roots, unsupported links and size overflow have candidate source-rejection receipts; uncertain capture is unresolved; daemon, monitor, setup, storage and cleanup faults remain infrastructure failures. A failed build carries its category, evidence, cleanup state and saved source. Publication failures retain bounded pending data for storage retry without execution replay.
